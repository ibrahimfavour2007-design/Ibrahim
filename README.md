Here is the breakdown of these five core version control and Git terms:
1. Version Control
A system that tracks and records changes to a file or set of files over time. It allows you to revert to earlier versions, compare changes, see who made specific modifications, and collaborate with others without the risk of overwriting someone else's work.
2. Repository (Repo)
A storage space—either on your local computer or on a remote server like GitHub—where your project's files, code, and complete historical record of all changes are kept.
3. Commit
A snapshot of your project at a specific point in time. When you make a "commit," you are saving your current progress to the repository's history along with a short, descriptive message explaining what changes were made and why. Think of it as a save point in a video game.
4. Branch
An independent, parallel line of development. By default, projects have a main line (often called main or master). A branch lets you copy that line so you can experiment, build a new feature, or fix a bug in isolation without affecting the stable code on the main line.
5. Merge
The process of combining changes from one branch into another. For example, once you finish building a new feature on your separate branch, you "merge" those changes back into the main branch so everyone has access to the updated code.
